## 1. 项目背景与基本情况

公司目前业主报修依赖电话与纸质工单：业主打电话到物业前台，客服手工登记，联系维修工上门，维修完成后无系统化记录。业主无法查询进度，重复催单，客服压力大。公司内部有一套使用多年的老工单系统（仅物业端可用），本次建设业主报修小程序，与老系统打通，形成报修闭环。

## 2. 目标与收益

- 报修工单线上化率 100%，纸质工单废除
- 业主满意度评分从 3.8 提升至 4.5（5 分制）
- 维修工单平均响应时长 < 30 分钟
- 客服接报修电话量下降 40%

## 3. 方案概述

- 业主端：微信小程序（业主提交报修、查看进度、确认完工、评价）
- 物业端：Web 管理后台（客服审核派单、维修工接单、项目经理看报表）
- 复用公司统一账号体系（业主手机号注册，物业内部员工用企业账号）
- 与老工单系统单向同步：小程序侧工单状态变化推送到老系统，老系统数据只读

## 4. 范围与 MVP

MVP 范围：

1. 业主报修上报（拍照、问题类型、房屋信息自动带出）
2. 客服审核与派单
3. 维修工接单、填报完工
4. 业主确认完工、评价
5. 进度消息通知（站内）

暂缓：自动派单算法、物料管理、多小区、在线支付。

## 5. 功能需求

### 5.1 模块规划

| 模块 | 归属端 | 功能 |
|------|--------|------|
| A 报修上报 | 业主端 | 报修表单、房屋选择、历史报修 |
| B 工单管理 | 物业端 | 工单列表、审核、派单、完工填报 |
| C 评价 | 业主端 | 完工后评价（星级 + 文字） |

### 5.2 模块详情（节选）

**A1 报修表单**：房屋信息（自动带出）、问题类型（漏水/电路/门窗/其他）、照片上传（最多 3 张）、文字描述（选填）、联系电话（自动带出）。

**B1 工单列表**：按状态筛选（待审核/已派单/维修中/待确认/已完成）、关键字搜索（房号/业主名）、每行显示工单号、状态、问题类型、提交时间。

**B2 派单**：客服在工单详情页选择维修工下拉框派单，保存后工单状态变更为"已派单"。

**C1 评价页**：工单"已完成"后业主可评价，星级 1-5 + 文字评价，提交后不可修改。

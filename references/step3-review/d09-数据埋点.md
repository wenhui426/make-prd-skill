# 数据埋点检查

> Supporting reference for the `make-prd` skill（STEP 3 质量审查）。在执行数据埋点检查时加载；单独使用时请先提供待检查的 PRD 内容。审查对象：新第6章"数据埋点"。
> **适用范围**：自研系统和商业化产品都需要，差异仅在是否还需要商业化指标。

## 维度说明

数据埋点是数据驱动运营的基础。产品上线后的效果评估、迭代决策、问题诊断都依赖埋点数据的质量。如果埋点设计缺失或混乱，后续任何数据分析都无从谈起。《决胜B端》产品监控的指标体系设计覆盖用户数据、行为数据、业务数据、技术数据四类，通过行为漏斗、页面转化率、用户留存等数据持续指导产品迭代，而非仅依赖主观判断。

**核心理论框架：**

1. **产品监控指标体系**（《决胜B端》产品监控的指标体系设计）：覆盖用户数据、行为数据、业务数据、技术数据四类。
   - **用户数据**：用户类型（新用户/老用户），用户行为状态（活跃用户/流失用户/沉睡用户）
   - **行为数据**：活跃度（PV、UV、访问深度、访问时长），访问路径（行为漏斗、页面转化率），质量（弹出率、退出率、留存率）
   - **业务数据**：结果数据（GMV/销售额/转化率/满意度），过程数据（拜访量/通话时长/货损率等业务过程指标）
   - **技术数据**：接口调用（API调用次数），系统性能（并发量、流量、错误率）

2. **数据驱动运营**（《决胜B端》第10章）：通过行为漏斗、页面转化率、用户留存等数据持续指导产品迭代。

## 检查清单

### 9.1 埋点范围与核心事件

- [ ] **核心操作路径覆盖**
  - 检查内容：埋点是否覆盖了产品的核心操作路径和关键转化节点
  - 优质标准：覆盖核心流程的每一步关键操作（如"创建订单→支付→发货→签收"每步都有埋点）、关键按钮、关键页面（首页/列表页/详情页/转化页）
  - 问题标志：只有零散的几个埋点，核心业务闭环的关键节点无埋点；或只有页面级埋点而无操作级埋点
  - 参考依据：新第6章数据埋点——"按公司统一标准描述需要监控的按钮、页面、事件"

- [ ] **埋点与指标对应**
  - 检查内容：第6章埋点是否能支撑第2章定义的成功指标和效果跟踪需求
  - 优质标准：每个成功指标都能对应到具体的埋点事件（指标→事件→页面/操作的完整链路），反向追溯时每个埋点都能说明它服务什么分析目的
  - 问题标志：定义了指标但不知道数据从哪来、如何采集；或埋了一堆点但说不清用途
  - 参考依据：《决胜B端》产品监控的指标体系设计

### 9.2 用户数据与行为数据

- [ ] **用户数据定义**
  - 检查内容：是否定义了观察用户状态的指标
  - 优质标准：覆盖用户类型（新用户/老用户）、用户行为状态（活跃用户/流失用户/沉睡用户），并有明确的判定规则（如"30天未登录定义为流失"）
  - 问题标志：只有结果指标（如销售额），没有用户分层数据
  - 参考依据：《决胜B端》产品监控的指标体系设计

- [ ] **行为数据定义**
  - 检查内容：是否定义了衡量用户使用行为的指标
  - 优质标准：覆盖活跃度（PV、UV、访问深度、访问时长）、访问路径（行为漏斗、页面转化率）、质量（弹出率、退出率、留存率）
  - 问题标志：只有结果指标，没有行为数据；出了问题无法诊断原因
  - 参考依据：《决胜B端》产品监控的指标体系设计

### 9.3 业务数据与技术数据

- [ ] **业务数据定义**
  - 检查内容：是否定义了衡量业务效果的指标
  - 优质标准：覆盖结果数据（GMV/销售额/转化率/满意度）和过程数据（拜访量/通话时长/货损率等业务过程指标）
  - 问题标志：指标全是结果指标，缺过程数据，无法定位问题出在业务链路的哪一环
  - 参考依据：《决胜B端》产品监控的指标体系设计

- [ ] **技术数据定义**
  - 检查内容：是否定义了衡量系统健康的指标
  - 优质标准：覆盖接口调用（API调用次数）、系统性能（并发量、流量、错误率）
  - 问题标志：技术健康无人监控，系统出问题只能靠用户反馈
  - 参考依据：《决胜B端》产品监控的指标体系设计

### 9.4 数据采集方案

- [ ] **埋点事件规范**
  - 检查内容：埋点设计是否标注了事件名称、触发条件、采集参数
  - 优质标准：每个埋点事件有统一命名规范（如"事件名-页面-操作"），触发条件明确（点击/曝光/停留），采集参数齐全（用户ID、时间戳、业务上下文）
  - 问题标志：只有"后续补充"的占位符，或埋点描述无法指导开发实现
  - 参考依据：新第6章数据埋点章节要求

- [ ] **数据采集频率与维度**
  - 检查内容：是否说明了数据采集频率和分析维度
  - 优质标准：定义了采集频率（实时/离线）、数据分析维度（时间维度/角色维度/租户维度）、数据归属（按组织架构/按角色/按客户）
  - 问题标志：定义了指标但不知道数据如何采集、如何归集
  - 参考依据：《决胜B端》产品监控的指标体系设计

## 常见问题诊断

| 问题现象 | 根本原因 | 改进方向 |
|---------|---------|---------|
| 只有结果指标，没有行为数据 | 未建立完整指标体系 | 补充用户数据、行为数据、业务数据、技术数据四类指标 |
| 核心转化节点无埋点 | 埋点设计未覆盖业务闭环 | 沿着核心业务流程逐节点检查埋点覆盖 |
| 指标定义了但不知道数据从哪来 | 埋点与指标脱节 | 建立"指标→事件→页面"的映射表 |
| 埋点描述模糊（"后续补充"） | 埋点设计未落地 | 按事件名称+触发条件+采集参数三要素定义每个埋点 |
| 技术健康无人监控 | 缺少技术数据维度 | 补充API调用、并发量、错误率等技术指标 |

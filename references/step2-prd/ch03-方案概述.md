## make-prd-ch03

# 第3章 方案概述 — 生成指引

> 生成 PRD 第3章"方案概述"的指引文件。

## 章节目标

用简要语言概述核心功能和项目方案，让读者在深入细节前对整体方案有全局认知。

> 💡 方法论基础：《决胜B端》自顶向下设计思路 — 先全景后细节

## 生成结构

```md
## 3、方案概述

### 3.1 产品方案概述

#### 3.1.1 核心功能概述

本项目包含以下核心功能模块：

| 序号 | 功能模块 | 功能简述 | 优先级 |
| --- | --- | --- | --- |
| 1 | {模块名称} | {一句话描述} | P0/P1/P2 |
| 2 | | | |

#### 3.1.2 方案概述

- **产品方案**：{核心产品策略，1-2句}
- **技术方案**：{关键技术选型或约束，1-2句}
- **运营方案**：{上线和推广策略概要，1-2句}

### 3.2 非功能需求

| 序号 | 需求 | 说明 |
|------|------|------|
| 1 | {性能需求：如响应时间、并发量} | |
| 2 | {可用性/可靠性} | |
| 3 | {安全与审计} | |
| 4 | {兼容性} | |
```

## 生成规则

### 3.1 产品方案概述

1. 功能模块从产品规划的"页面流程"和"范围边界"提取，按业务逻辑（而非技术模块）组织。
2. 优先级标注：P0=必须有、P1=应该有、P2=可以有。
3. 方案概述不展开细节，每个维度 1-2 句话即可，细节在后续章节（第 5 章功能需求）。

### 3.2 非功能需求

1. **性能需求必须有**：响应时间、并发量、吞吐量等，至少列 1 条。
2. 其他非功能需求（可用性、安全与审计、数据保留、可靠性、兼容性、可维护性）根据产品定型稿和系统复杂度按需补充；分析后没有必要可以不写。
3. 交易型/基础服务型产品重点关注性能和稳定性；涉及数据隐私的补充安全与审计。

## 质量标准

- [ ] 功能模块按业务逻辑组织，不按技术分
- [ ] 每个模块有清晰的一句话描述
- [ ] 有明确的优先级标注
- [ ] 性能需求已覆盖

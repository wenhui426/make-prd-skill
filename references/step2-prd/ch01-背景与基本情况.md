# 第1章 项目背景与基本情况 — 生成指引

> 基于冻结版产品规划（`01-产品规划.md`）和用户提供的业务上下文，生成 PRD 第1章"项目背景与基本情况"的指引文件。信息来自产品规划，不重复收集。

## 章节目标

清晰描述项目的来龙去脉和需求基本信息，让文档阅读者理解项目为什么要做、为谁做、解决什么。

> 💡 方法论基础：《决胜B端》三层业务调研框架（战略层→战术层→执行层）+ 需求发现十三要素五步法（第一步"分析角色"+ 第二步"了解基本场景"）

## 生成规则

### 1.1 项目背景

1. **业务现状**：从产品规划的"基本描述"提取组织背景、业务模式、现有系统，用简洁段落描述。
2. **面临问题**：按"影响范围 × 严重程度 × 紧迫度"排序，每个问题一句话概括+一句话展开。
3. **解决思路**：提炼产品规划的"实现价值"和方案方向，用 1-2 段概括。
4. **决策依据**：产品规划中如有数据（效率数据、成本数据、业务量数据），整理为要点列表。

### 1.2 需求基本情况

1. **角色分析**：从产品规划的"目标用户"识别所有角色，按"十三要素"三类（提出人、使用人、受影响人）分类。
2. **场景描述**：用场景六要素完整描述，确保每个场景是具体的业务故事，而不是抽象功能描述。承接产品规划的"JTBD 场景"。
3. **痛点挖掘**：用"五个为什么"（5Why）思路，从表面需求追溯到根本痛点。
4. **频率和价值**：从产品规划的业务数据中推断。

### 不同产品类型的侧重

| 产品类型 | 背景侧重点 |
| --- | --- |
| 商业化产品 | 市场机会、客户痛点、商业价值假设 |
| 企业自研系统 | 业务现状（带数据）、效率瓶颈、管理层诉求 |

### 关键区分

| 概念 | 说明 | 示例 |
| --- | --- | --- |
| 需求提出人 | 提出这个需求的人（可能是管理层） | 销售总监 |
| 功能使用人 | 实际使用功能的人 | 一线销售人员 |
| 受影响人 | 不直接使用但工作受影响的人 | 财务（收到销售提交的报销） |

### 信息不足时

- 业务现状：基于产品类型生成框架性描述，用 `[TODO: 请补充具体的业务数据，如日均订单量、团队规模、现有系统名称等]` 标注。
- 面临问题：如果只有一句话需求，推断 2-3 个可能的业务痛点（基于产品类型常见问题），标注 `[TODO: 请确认以下问题是否准确，并补充优先级]`。
- 角色：推断可能的使用角色，标注 `[TODO: 请确认角色列表是否完整]`。
- 场景：至少生成 1 个主场景框架，用 `[TODO]` 标注缺失的六要素。

## 质量标准

- [ ] 背景描述有具体的业务场景，不空泛
- [ ] 问题描述有优先级排序
- [ ] 解决思路与问题一一对应
- [ ] 尽可能有数据支撑（即使是用户提供的粗略数据）
- [ ] 三类角色（提出人/使用人/受影响人）都已识别
- [ ] 至少有 1 个核心场景用六要素完整描述
- [ ] 痛点描述具体，不是"提升效率"这类空话
- [ ] 频率和价值有估算（即使是粗略的）

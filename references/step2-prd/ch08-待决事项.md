## make-prd-ch08

# 第8章 待决事项 — 生成指引

> 生成 PRD 第8章"待决事项"的指引文件。本章集中记录 PRD 写作全程尚未确定、需要继续确认的事项，与 [assets/02-PRD模板.md](../../assets/02-PRD模板.md) 第 8 章的编号方式一致。

## 章节目标

集中管理所有待决策事项，确保问题被跟踪而不是被遗忘，不把未解决问题藏在正文里，不把模型假设伪装成已确认事实。

## 生成结构

```md
## 8、待决事项

| 编号 | 来源章节/模块 | 待决策内容 | 影响 | 阻塞 | 当前处理/默认假设 | 负责人 | 状态 | 提出时间 | 关闭时间 |
|------|---------------|------------|------|------|-------------------|--------|------|----------|----------|
| D001 |               |            |      | 是/否 |                   |        | Open |          |          |
```

## 生成规则

1. **编号方式（与 PRD 模板一致）**：ID 使用 `D001`、`D002` 连续编号，**不与功能 ID（FXX）、规则 ID（R）、验收标准 ID（AC）混用**。
2. **自动收集**：写作任意阶段遇到需要用户补充、确认或裁决的功能、规则、范围、权限、数据、流程、异常、验收、优先级、依赖或其他内容，立即写入本章——不要因为不阻塞当前段落就忽略或散落在聊天记录里；回顾前面所有章节中标注的 `[TODO]` 项，将需要决策的（而非纯信息补充的）汇总到此表。
3. **阻塞分级**：阻塞项（影响后续写作）先请用户确认；非阻塞项可带临时假设继续推进，但**临时假设不能视为已确认结论**，不得标记为已确认。
4. **每项都要有负责人和时间**：即使当前未知，也要标注 `[TODO: 请指定负责人]`。
5. **数量控制**：待决事项超过 10 项，说明 PRD 成熟度不足，提醒用户先解决核心待决事项再提交评审。
6. **关闭纪律**：已关闭事项保留在表中，通过状态字段标记（`Closed`），不从记录中删除；用户确认后更新状态和关闭时间，必要时同步修订相关章节。

## 质量标准

- [ ] 所有需要决策的 TODO 都已汇总到此表
- [ ] 编号为 D001 起连续，不与功能/规则/验收编号混用
- [ ] 每项有来源、影响、阻塞标记（或标注待指定）
- [ ] 每项有负责人（或标注待指定）
- [ ] 总数不超过 10 项（否则给出警告）

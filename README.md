# make-prd · 产品设计全流程流水线

> 把"模糊想法"变成"可评审的 PRD"，再把 PRD 审出盲区。
> 面向产品经理：一个 skill 覆盖 产品规划 → PRD 生成 → 质量审查 → 修订闭环 → 收尾交付 的完整链路。

## 是什么

传统工作流里，产品想法靠聊天收敛、PRD 靠空白文档硬写、审查靠经验和运气。make-prd 把这套流程标准化成六步流水线，每一步都有明确的产出物和确认节点：

```
STEP 0 开工确认 ──▶ STEP 1 产品规划 ──▶ STEP 2 PRD 生成 ──▶ STEP 3 质量审查 ──▶ STEP 4 修订闭环 ──▶ STEP 5 收尾交付
（想法+资料）        （定型稿★）          （PRD.md★）         （审查报告★）        （修订后PRD★）      （交付说明★）
```

| 环节 | 做什么 | 产出 |
|------|--------|------|
| 0 开工确认 | 生成目录/材料盘点/起点状态/用途/版本号 5 项确认，初始化工作区 | 输入材料/ + PRD文档/ |
| 1 产品规划 | 逐节填充（基本描述/实现价值/JTBD/范围/页面流程/开放问题）并冻结 | 01-产品规划.md（冻结版定型稿★） |
| 2 PRD 生成 | 8 核心章 + 4 可选章（14 章裁剪），模块规划先行、逐模块分步输出 | 02-PRD.md（含修改记录表★） |
| 3 质量审查 | 13 维度（12 常驻 + AI 按需）逐项检查，R1-R8 重大风险排查 | 03-质量审查报告.md（P0-P3 问题清单★） |
| 4 修订闭环 | 按优先级分批、逐条确认修改方案修订，复查闭环 | 修订后 02-PRD.md + 报告复查记录★ |
| 5 收尾交付 | 交付清单核对 + 交付说明 | 04-交付说明.md + 全套产物★ |

## 怎么安装（Claude Code）

1. 下载本仓库（或 `git clone https://github.com/wenhui426/make-prd-skill.git`）
2. 把整个 `make-prd-skill/` 目录放进你的 Claude 技能目录（如 `~/.claude/skills/make-prd-skill/`）
3. 重启 Claude Code，技能即可用

> 支持 Claude Code 的 skills 机制；其他支持 skills 的 Claude 客户端同理，把目录放到对应技能目录即可。

## 怎么用（自然语言触发）

| 你想做的事 | 怎么说 |
|-----------|--------|
| 想法还没成型 | "帮我把这个想法收敛一下：我要做一个 XX 系统…" |
| 要一份完整 PRD | "帮我写份 PRD，背景是…" / "按这份需求文档生成 PRD" |
| 有定型稿/旧 PRD | "我有定型稿了，帮我写 PRD"（从 STEP 2 进入） |
| 审已有 PRD | "帮我看看这份 PRD 有什么漏洞" / "审一下这个 B端方案" / "帮我做个 PRD 评审" |

每一步完成后都会停下来等确认；生成目录由你指定，版本号贯穿全流程文档。

## 质量保障

- **不猜**：信息缺失一律标记（开放问题 / `[TODO]` / 待决策事项），等你确认，不编造
- **确认在聊天里**：每轮确认点完整列在回复中，你不用自己打开文件就能评审
- **来源可溯**：需求、规则、范围、假设都能追溯到用户或用户提供的材料
- **产物落文件**：定型稿、PRD、审查报告、交付说明都是文件，可存档、可追溯、可断点续写

## 文件结构

```
make-prd/
├── SKILL.md                  # 六步流程主指令
├── README.md                 # 本文件，给人看的说明
├── assets/                   # 模板
│   ├── 01-产品规划模板.md      # STEP 1 定型稿模板
│   └── 02-PRD模板.md          # STEP 2 PRD 骨架模板
└── references/               # 按需加载的指引
    ├── step2-prd/            # STEP 2 各章节生成指引（ch01-ch08、可选 ca/cb/cd、typing、selfcheck）
    └── step3-review/         # STEP 3 质量审查（d01-d13 维度清单 + guide 报告模板 + veto 重大风险）
```

## 对接

最终产物 02-PRD.md 可交给 **prd-html** skill 直接生成交互原型界面。

## 评测

带这条流程跑 vs 裸模型：任务通过率 **100%** vs **76%**。裸模型内容质量并不差，差的全是格式标准化（无修改记录表、表头字段乱起、文件名无编号）——skill 的增量是结构纪律，保证产物可衔接下游。

## 来源与版本说明

make-prd v2 整合自 `pm` skill 集合（pm-make/prd-make/create-prd/check-prd 四个子 skill，其中 create-prd 与 check-prd 来自杨堃开源仓库）。v2 版本将 14 章 PRD 结构裁剪为 8 核心章 + 4 可选章，审查维度合并为 13 个，形成六步流水线闭环。
